# GiveON

<img src="assets/giveon-icon.png" alt="GiveON 아이콘" width="160" />

승인·인증·개별 상품 지급을 지원하는 한국어 디스코드 이벤트 봇입니다. **MIT 라이선스**로 누구나 복제·수정·직접 운영할 수 있습니다. Node.js **24 LTS 권장**, 최소22.16.0. 프로젝트 설정에서 **SQLite 또는 MySQL 중 하나**를 선택합니다. 기본값인 내장 SQLite는 별도 DB 서버나 네이티브 모듈 빌드가 필요하지 않습니다.

**관리자가 `/init`으로 초기설정 팝업을 열고 완료하면 선택한 채널에 신청 안내를 게시합니다.** 일반 이용은 버튼·선택 메뉴·입력창으로, 설정·관리는 `/setting`으로 진행합니다. 서버 입장이나 재시작 시 안내를 자동 게시하지 않습니다.

## 안내 패널

| 버튼 | 기능 |
|---|---|
| 이벤트 신청 | 사전 템플릿 또는 직접 설정을 고르고 순서대로 신청 |
| 내 신청 | 내 이벤트 등록·승인 요청·취소, 내 이벤트 인증 대기에서 주최자 검수 |
| 내 당첨 | 수령, 인증 제출·보완, 상태 확인, DM 실패 재시도 |
| 이용 안내 | 진행 방법과 수령 규칙 |

입력과 관리 화면은 본인에게만 보이는 응답입니다. 상품 등록과 인증 입력창에서 **텍스트, 이미지 또는 둘 다** 제출할 수 있습니다. 이미지는 최대2장, 합계8MiB, PNG·JPG·GIF·WebP를 지원합니다. Discord 첨부만 읽고 실제 파일 서명을 확인하며 SVG는 지원하지 않습니다.

공개 안내에는 관리자 버튼이 없습니다. 봇 소유자 또는 등록된 관리 역할은 초기설정 완료 후 **`/setting`**으로 본인에게만 보이는 설정·관리 화면을 엽니다. 여기에서 채널·역할·템플릿 설정, 신청 승인·거절, 신고·주최 제한, 부분 리롤과 지급 결과 확인을 진행합니다. 인증 검수는 **주최자 개인 DM 또는 내 신청 → 내 이벤트 인증 대기**에서 주최자만 처리합니다. 초기설정 완료 전에는 `/init`을 먼저 진행하도록 안내합니다.

개인 화면의 **닫기**(이전 돌아가기) 버튼은 해당 개인 응답을 닫습니다. 공개 신청 안내를 개인 응답에 다시 복제하지 않습니다.

이벤트 카드의 **상세 보기**에서 총 참여 인원과 참여자 목록을 본인에게만 보이는 화면으로 확인합니다. 한 페이지에25명씩 표시하며 이전·다음·새로고침으로 현재 참여 신청 목록을 볼 수 있습니다. 공개 카드에는 참여자 전용 버튼을 추가하지 않습니다.

`/init`은 봇 소유자 또는 등록된 관리 역할만 사용할 수 있으며 실행자에게만 채널 설정 팝업이 열립니다. 역할 설정 팝업과 비공개 최종 확인을 거쳐 **완료·게시**를 누를 때만 설정을 저장하고 안내를 게시합니다. 같은 게시 채널을 고르면 기존 안내를 갱신하고, 다른 채널을 고르면 새 안내를 게시한 뒤 봇이 만든 이전 안내를 정리합니다. 명령 실행 채널과 게시 채널은 달라도 됩니다. 승인된 실제 이벤트와 당첨 알림은 별도 게시물입니다.

## 진행 규칙

- 신청1건=이벤트1개, 상품 한 종류. 서로 다른 상품은 각각 신청합니다.
- 이벤트마다1~100명의 당첨 인원을 지정합니다. **디지털 자동 전달**은 각 자리마다 상품 내용을 사전 등록합니다. **실물·직접 전달**은 개별 코드 없이 주최자 연락 안내를 자동 준비합니다. 방식 변경 시 기존 등록 내용을 삭제하기 전에 확인합니다.
- 신청 → 관리 채널 승인·거절 → 공개 채널 게시 → 참여 버튼 → 마감 추첨. 주최자는 본문에 한 번 표시하고 알림 역할만 별도로 멘션합니다.
- 한 이벤트의1·2·3번 자리는 한 사람당 하나만 당첨됩니다. 별도로 신청한 이벤트3개에서는 같은 사람이 각각 당첨될 수 있습니다. 리롤된 사람은 해당 이벤트에서만 재당첨 제외됩니다.
- 추첨은 `crypto.randomInt()`로 Fisher–Yates 섞기3회 후 균등 선택하며, 같은 이벤트에서 이전에 당첨된 사람을 다시 뽑지 않습니다. 균등 난수는 목록 앞뒤의 당첨 확률도 같습니다.
- 일반 수령: 당첨 → 수령 버튼 → 상품 DM → 완료.
- 인증 수령: 당첨 → 수령 버튼 → 수령 타이머 정지 및 인증 입력창 → **5분 내 텍스트·사진 제출** → 검수 대기 → 승인 → 자동 DM.
- 검수 대기에는 기한이 없습니다. **보완 요청 시 새5분**을 부여합니다. 당첨자는 보완 DM의 **보완 제출** 버튼 또는 내 당첨에서 사진·메시지 입력창을 다시 열 수 있습니다. 반복해서 열어도 기한은 늘어나지 않습니다. 주최자 DM이 닫혀 있으면 내 신청의 인증 대기를 이용하며 관리자에게 원문을 우회 전달하지 않습니다.
- 기한 내 접수한 첨부는 최대60초 동안 내려받으며 파일 처리 중에는 리롤하지 않습니다. 실패하면 원래 기한으로 돌아갑니다.
- 미수령·미제출·미보완·최종 거절은 해당 자리만 리롤합니다. 이미 지급한 자리는 유지합니다. 후보가 없으면 마감합니다.

## 설치

### 1. Discord 애플리케이션

[Discord Developer Portal](https://discord.com/developers/applications)에서 자기 애플리케이션과 Bot을 준비합니다.

- OAuth2 설치 범위: `bot`, `applications.commands`.
- 봇 권한: **채널 보기, 메시지 보내기, 링크 임베드, 파일 첨부, 메시지 기록 보기**.
- 전체 관리자 권한과 Message Content·Server Members Intent는 필요하지 않습니다. 역할은 사용자별 REST 조회로 확인합니다.
- 시작 알림 역할은 서버에서 멘션 가능하도록 설정합니다.
- 당첨 알림에 답장으로 `reroll` 또는 `리롤`을 쓰면 봇 소유자·등록 관리 역할만 해당 자리를 강제 리롤할 수 있습니다. **답장할 때 봇 멘션을 켜두세요.** Message Content 특권 없이 멘션한 답장만 읽습니다. 지급 완료·전송 결과 불명인 건은 리롤하지 않습니다. 이전 당첨자는 해당 이벤트에서 재당첨되지 않습니다.
- 새 당첨 안내와 마감 알림은 원본 이벤트 메시지에 답장으로 게시합니다. 이벤트 공개 채널 설정을 바꿔도 해당 이벤트의 원래 채널을 사용합니다. 원본을 삭제한 경우에는 일반 알림으로 전송합니다.
- 개발자 모드에서 본인 사용자 ID와 Application ID를 확인합니다.

### 2. 환경 설정

```sh
git clone https://github.com/kjheeee/GiveON.git
cd GiveON
npm ci
```

`.env.example`을 `.env`로 복사합니다.

```powershell
# Windows PowerShell
Copy-Item .env.example .env
```

```sh
# macOS / Linux
cp .env.example .env
```

```sh
npm run keygen
```

생성한 키를 `.env`의 `DATA_KEY`에 넣습니다.

| 변수 | 내용 |
|---|---|
| `DISCORD_TOKEN` | 자기 봇의 토큰 |
| `APPLICATION_ID` | Discord 애플리케이션 ID |
| `OWNER_IDS` | 소유자 사용자 ID, 여러 명이면 쉼표 구분 |
| `DATA_KEY` | 생성한64자리16진수 키 |
| `DATABASE_PATH` | 기본 `./data/giveaway.sqlite` |
| `DB_DRIVER` | `sqlite`(기본값) 또는 `mysql` |
| `DEV_GUILD_ID` | 개발 서버 명령 등록용 서버 ID. 비우면 전역 등록 |

`.env`와 DB는 Git 제외 대상입니다. **운영 중 DATA_KEY를 바꾸면 기존 자료를 읽을 수 없습니다.** 키와 데이터 폴더의 접근 권한을 제한하세요. 하나의 DB에는 단일 프로세스만 실행합니다.

### 3. 등록·실행

```sh
npm run register
npm start
```

명령 등록은 해당 애플리케이션·범위의 명령 목록을 관리자용 `/init`, `/setting` 두 개로 교체합니다. 전역 명령은 Discord에 반영될 때까지 시간이 걸릴 수 있습니다. 개발 중에는 `DEV_GUILD_ID`를 사용할 수 있습니다.

### DB 선택

프로젝트 `.env`의 `DB_DRIVER`로 전체 봇이 사용할 DB 하나를 선택합니다. 서버별 Discord 설정이 아닙니다.

```dotenv
# 기본값: 기존 파일 사용
DB_DRIVER=sqlite
DATABASE_PATH=./data/giveaway.sqlite
```

MySQL을 쓰려면 **MySQL 8.0.19 이상(8.4 권장)**에 빈 DB와 전용 사용자를 만든 뒤 다음처럼 설정합니다. 필요한 테이블은 봇이 생성합니다.

```dotenv
DB_DRIVER=mysql
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=giveon
MYSQL_PASSWORD=your-database-password
MYSQL_DATABASE=giveon
MYSQL_TIMEOUT_MS=5000
MYSQL_SSL=false
```

MySQL 계정은 선택한 DB 안의 테이블 생성·조회·수정 권한이 필요합니다. `utf8mb4`/InnoDB를 사용하고 `max_allowed_packet`은 최소16MiB, 32MiB 이상을 권장합니다. TLS는 `MYSQL_SSL=true`, 사설 CA는 `MYSQL_SSL_CA_FILE`로 지정합니다. 인증서 검증을 끄지 않습니다. MariaDB는 지원 대상으로 검증하지 않았습니다.

DB를 바꾸면 다른 저장소를 여는 것이므로 기존 데이터가 자동 이관되지는 않습니다. SQLite와 MySQL을 동시에 쓰거나 연결 실패 시 다른 DB로 대체하지 않습니다. 같은 DB에는 봇 프로세스 하나만 실행합니다.

### 4. 패널 게시와 초기 설정

1. 봇을 서버에 추가합니다.
2. `.env`의 소유자가 서버에서 **`/init`**을 실행합니다. 실행자에게만 실제 팝업이 열립니다.
3. 첫 팝업에서 **신청 안내 채널 / 이벤트 공개 채널 / 승인·검수 채널**을 선택하고 제출합니다. 아직 설정 저장이나 안내 게시를 하지 않습니다.
4. 본인에게만 보이는 **다음 · 역할 설정** 버튼으로 두 번째 팝업을 엽니다. 관리 역할, 조건 후보 역할, 공통 참여 금지 역할, 시작 알림 역할을 선택합니다. 역할은 모두 선택 사항이며 관리 역할은 봇 소유자만 편집합니다.
5. **조건 후보 역할**은 신청자가 참여 가능·차단 조건에서 선택할 수 있는 목록입니다. 이 역할의 보유 자체가 관리 권한을 주지는 않습니다.
6. 제출 후 비공개 최종 확인에서 **완료·게시**를 누릅니다. 이때 설정을 저장하고 선택한 신청 안내 채널에 버튼 안내를 게시합니다. 완료 전 취소는 기존 설정을 바꾸지 않습니다. 이후에는 **`/setting` → 설정**에서 수정할 수 있습니다.

관리 역할 등록·제거는 봇 소유자만 할 수 있습니다. 지정 관리 역할은 승인·검수와 다른 설정을 담당합니다. Discord Administrator 권한 자체를 봇의 관리 권한으로 간주하지 않습니다.

관리 채널은 `@everyone`에게 비공개여야 합니다. 다른 일반 역할에도 별도 보기 허용이 없는지 확인하세요. 관리 채널은 이벤트 공개·신청 안내 채널과 달라야 하며, 이벤트 공개와 신청 안내 채널은 같아도 됩니다. 게시 실패 시 최종 확인에서 재시도할 수 있습니다.

## 신청 예시

치킨 교환권2장을2명에게 주려면 다음처럼 진행합니다.

1. **이벤트 신청 → 직접 설정**에서 상품명·설명·진행60분·수령30분·당첨2명을 입력합니다.
2. **참여 조건**에서 등록된 참여 가능·차단 역할을 선택하고 다음을 누릅니다. 같은 역할을 양쪽에 넣을 수 없으며, 한쪽에서 고른 역할은 반대쪽 후보에서 빠집니다.
3. **인증 여부**를 선택합니다. 필요하면 인증 안내를 입력합니다.
4. **1번 상품 입력**에 메시지·이미지를 등록하면 **2번 상품**으로 자동 이동합니다. 자리 번호를 직접 입력하지 않습니다.
5. 모두 등록하면 **최종 확인 → 승인 요청**으로 진행합니다. 나중에 **내 신청**을 열면 이어서 진행할 수 있습니다.

사전 템플릿을 고르면 조건·인증 단계를 반복하지 않고 상품명·시간·인원 입력 후 상품 등록으로 바로 이어집니다.

허용 역할 여러 개는 하나 이상 보유하면 충족합니다. 거절 또는 공통 금지 역할이 있으면 참여할 수 없습니다. 참여·추첨·수령 시 다시 확인합니다. 봇은 참여하지 못하고 주최자 참여는 허용합니다.

## 사전 템플릿

관리자의 **`/setting` → 템플릿 → 새 템플릿**에서 이름·공개 문구를 입력하고, 참여 가능·차단 역할과 인증 안내를 설정한 뒤 **사용 시작**을 누릅니다. 예를 들어 기본·30렙·50렙 안내를 서버 운영자가 미리 등록할 수 있습니다. 레벨 역할은 실제 서버의 등록된 역할을 직접 연결해야 합니다.

- 템플릿에는 **문구·참여/차단 역할·인증**만 저장합니다. 시간·인원은 신청자가 입력하며 상품 코드·교환권·인증 자료는 템플릿에 넣지 않습니다.
- 템플릿 조건은 함께 적용됩니다. 개별 조건을 바꾸려면 다른 템플릿을 선택하거나 직접 설정으로 전환합니다.
- 같은 역할의 허용·차단 중복, 공통 차단 역할의 허용, 미등록 역할은 저장·신청 단계에서도 차단합니다.
- 템플릿이 변경되거나 중지되면 기존 초안에서 최신 템플릿을 다시 선택해 확인해야 합니다. 다시 선택해도 시간·인원·이미 등록한 상품은 보존합니다.
- 진행 중인 승인 이벤트의 조건은 템플릿을 수정해도 소급 변경하지 않습니다.

공개 이벤트는 임베드 대신 Discord Components V2의 본문 카드와 버튼으로 표시합니다. 안내 패널도 일반 본문을 사용합니다. Discord의 메시지 삭제 등 서버 권한 기능 자체를 비활성화하는 기능은 아닙니다.

초안에서만 상품·조건·인증 설정을 수정할 수 있습니다. 신청 후 수정이 필요하면 취소 후 새로 신청합니다.

## 비공개·삭제·실패 처리

상품 원문은 관리자에게 표시하지 않습니다. 인증 자료는 **해당 주최자만** 조회·승인·보완 요청·거절합니다. 봇 소유자·관리자도 다른 주최자의 자료를 볼 수 없습니다. 제출 버전을 확인해 오래된 자료의 승인을 차단합니다. 검수 승인 즉시 인증 원문을 삭제하며 상품 DM이 실패해도 다시 보관하지 않습니다.

지급은 **DM 전송 성공 → 지급 기록 저장과 해당 상품·인증 원문 삭제를 단일 DB 트랜잭션으로 처리**합니다. 상품 이미지는 URL만 보내지 않고 DM 첨부로 업로드합니다. 당첨자·검수자·처리시각·DM 메시지 ID 등의 기록은 남습니다. 이미 지운 상품은 봇에서 재전송할 수 없으므로 전달받은 DM을 보관하세요.

- 확정 DM 실패: 원문 보관, 당첨자의 내 당첨 → 상품 전달 다시 시도.
- 전송 후 타임아웃·전송 중 재시작: 결과 불명으로 보관, 자동 재전송·리롤 금지.
- 결과 불명: `/setting` → 지급 결과 확인에서 nonce·지급 번호를 최근 DM 최대1,000건과 대조합니다. 찾으면 완료·원문 삭제, 못 찾으면 수동 운영 확인이 필요합니다.
- 후보 없음·취소·신청 거절: 미지급 원문을 즉시 삭제합니다. 회수 기능은 없습니다. 업데이트 후 처음 기동할 때 기존 종료 건의 남은 상품 원문도 삭제합니다. 주최자는 원래 상품을 직접 보관해야 합니다.

## 실물 상품·기록 검색·신고

상품 등록 단계에서 **실물·직접 전달**을 고르면 수령(인증 필요 시 주최자 승인) 후 당첨자에게 주최자 멘션과 개인 DM 연락 안내를 보냅니다. 이름·주소·전화번호를 받는 봇 입력창은 만들지 않습니다. 공개 안내에도 직접 전달 방식을 표시하며 완료 상태는 **주최자 연락 안내 완료**입니다. 배송·실물 수령 완료를 의미하지 않습니다.

`/lookup id:giveaway-delivery:f6d376cd494a8d49`처럼 전달 식별자를 붙여 넣거나 이벤트·당첨 번호16자만 입력합니다. 당첨 건은 당첨자·주최자·관리자만 같은 서버에서 조회하며, 상품명·당첨자·상태·최근 처리 기록과 원 이벤트 링크를 표시합니다. 본인 수령 DM 링크는 당첨자에게만 표시합니다. 삭제된 상품·인증을 복구하거나 관리자에게 원문을 보여주지는 않습니다.

이벤트 상세 보기의 **이벤트 신고**, 내 당첨 또는 수령 DM의 **전달 내용 신고**에서 사유·사진 증거를 제출합니다. 입력창은 관리자에게 전달됨을 안내합니다. 당첨자 신고는 본인의 당첨 건만 허용합니다. 신고 내용·사진은 승인·신고 채널에 전송하며 **봇 DB에는 원문을 저장하지 않습니다**. DB에는 신고 번호·대상·신고자·접수 상태·관리 메시지 ID만 남습니다. 같은 이벤트의 미처리 중복 신고를 막고 하루5건으로 제한합니다. 전송 결과가 불명하면 자동 재전송하지 않으므로 신고 번호로 관리자에게 문의합니다.

관리자는 `/setting` → **신고 관리**에서 증거 링크를 확인하고 이벤트 취소, 주최 제한·해제, 처리 완료를 선택합니다. 주최 제한은 해당 서버의 신규 생성·초안 제출·승인을 막으며 진행 중인 이벤트는 별도 취소해야 합니다. 서버 강퇴·밴을 자동 실행하지 않습니다. 관리자에게 보이는 증거는 신고자가 직접 제출한 사본이며 원래 상품·인증 DB를 열어 주는 기능은 아닙니다.

SQLite는 AES-256-GCM/AAD 암호화, `secure_delete=ON`, rollback journal `DELETE`, `synchronous=FULL`을 사용합니다. 상품·인증 원문은 작업 큐·감사 로그에 넣지 않습니다.

**삭제 범위는 봇이 운영하는 현재 DB입니다.** Discord에 업로드한 첨부, 전달된 DM, 관리자 조회 사본, 별도 백업·스크린샷까지 지우는 기능은 아닙니다. 호스트와 암호화 키를 가진 운영자에게까지 원문을 숨긴다는 뜻도 아닙니다.

## Docker / PM2

```sh
docker compose build
docker compose run --rm bot node scripts/register.js
docker compose up -d
```

SQLite는 `giveaway-data` 볼륨에 저장하며 공개 HTTP 포트를 사용하지 않습니다. 기존 프로세스가 같은 DB를 사용하면 추가 실행하지 마세요. 비정상 종료 후 잠금 만료까지 최대60초 걸릴 수 있습니다.

기존 PM2를 사용한다면:

```sh
pm2 start ecosystem.config.cjs --only giveon
```

`GIVEON_ENV_FILE`, `GIVEON_LOG_DIR`, `GIVEON_NODE`로 환경 파일·로그·Node 경로를 지정할 수 있습니다. 여기에 비밀값 대신 경로만 넣습니다. `DATABASE_PATH`는 릴리스 밖의 영속 경로를 권장합니다. Gateway ready와 Windows shutdown 메시지를 지원합니다. 전체 PM2 목록 저장과 다른 앱 운영은 별도로 관리하세요.

## 개발·검증

```sh
npm run check
npm test
npm audit --omit=dev
```

테스트는 외부 Discord 메시지를 보내지 않고 가짜 전송 계층·격리 SQLite로 수행합니다. Windows의 테스트 파일 DB는 종료 후 휴지통으로 이동하며 실패 시 영구 삭제로 전환하지 않습니다.

실제 MySQL에서도 같은 기능 테스트를 실행할 수 있습니다. 별도로 만든 **`giveon_test` 또는 `giveon_test_*` 전용 DB**만 허용하며 테스트마다 해당 DB의 자료를 초기화합니다. `MYSQL_TEST_HOST`, `MYSQL_TEST_PORT`, `MYSQL_TEST_USER`, `MYSQL_TEST_PASSWORD`, `MYSQL_TEST_DATABASE`를 설정한 뒤 `npm run test:mysql`을 실행하세요. 운영 DB를 테스트 대상으로 지정하지 마세요.

패널은 DB에 메시지 ID를 저장하고 버튼은 고정 ID와 현재 권한을 확인하므로 재시작 후에도 작동합니다. 패널 전송 결과가 불명인데 기존 안내를 찾지 못하면 중복 게시를 막기 위해 보류합니다. 봇에게 필요한 채널·기록 읽기 권한을 확인하세요.
